# Родословная тейпа Хутиевых

Семейный сайт с деревом и историей Ляжги. Поиск ведёт к конкретному человеку и показывает цепочку его предков. Ссылку на открытую ветвь можно скопировать из адресной строки.

## Открыть на своём компьютере

На этом компьютере выберите **«Родословная Хутиевых»** в меню приложений. Ярлык запускает пользовательскую службу `khutiev-tree.service` и открывает сайт в браузере. Служба настроена на запуск при входе в систему и перезапуск после остановки процесса.

Для ручного запуска на другом компьютере нужен Node.js 22.13 или новее. В папке проекта выполните:

```sh
node server/local.mjs
```

Откройте http://127.0.0.1:4178 в браузере. Сервер по умолчанию доступен только на этом компьютере. Внешние библиотеки для запуска не требуются.

## Как пользоваться

При первом открытии выбран ингушский язык. Переключатель в заголовке даёт выбрать русский и запоминает выбор в браузере. Все имена и подтверждённые дополнения видны без входа. Дерево можно перемещать, приближать колёсиком или двумя пальцами. Поиск и цветные кнопки ветвей перемещают к выбранному месту. Кнопка «Всё древо» возвращает общий вид.

На общем виде четыре цвета обозначают четыре ваьра. При приближении фон имени показывает поколение, а цвет линии — ветвь. Отсчёт поколений идёт от Хути. Цветовую шкалу можно открыть кнопкой «Ноахалаш» («Поколения») внизу дерева.

Кнопка «Доккха алапаш» («Крупный шрифт») рядом с поиском увеличивает имена на полотне, в поисковой выдаче и карточке человека. Браузер запоминает выбор. Чтобы прочитать ветвь ещё крупнее, приблизьте её кнопкой «+» или разведите два пальца на экране.

Внизу справа нажмите «Ӏалашъе» («Сохранить») и выберите PDF или PNG. PDF содержит всё дерево на одной странице с возможностью поиска по именам. PNG сохраняет дерево как изображение. В обоих файлах и при обычной печати из браузера видны все имена, связи и шкала поколений при любом масштабе экрана.

Чтобы предложить сына, выберите его отца и заполните форму «Добавить сына». После подтверждения запись появится на общем полотне и войдёт в статистику. Чтобы предложить другое написание имени, откройте карточку человека и нажмите «Исправить имя». Редактор видит оба варианта в заявке.

Нажмите «Редактор» в шапке или откройте [вход редактора](http://127.0.0.1:4178/#editor). Локальный пароль хранится в `.family/editor-code.txt`. После входа доступна вкладка «Заявки». Если войти из карточки человека, она останется открытой, и исправление имени можно будет сохранить сразу.

Статистика строится по записям текущего дерева. Число предков в карточке — длина известной линии от Хути до отца выбранного человека. Число потомков включает все следующие поколения этой ветви. Раздел истории содержит текст семейной схемы и отдельно подписанные сведения из других источников.

## Источник и сохранность

Исходные 748 записей и 747 связей перенесены из семейного PDF с помощью векторных соединений между подписями. У Хути четыре ветви — Бейна, Заур, Каса и Харси. Совпадающие имена, вопросительный знак в записи «Дошк ?» и авторское написание сохранены. Цветовая шкала периодов не использовалась как дата рождения. Рассказ о тейпе обрывается посреди предложения в источнике, это отмечено в статье. [Схема в Coggle](https://coggle.it/diagram/XcQ0fJL8UlFIQ2zq/t/хути-silhouette)

Начальные записи находятся в `data/people.json`, история — в `data/history.json`. По уточнению семьи имя сына Мурада в ветви Заура записано как Мансур (в PDF — Мамсур). Последующие исправления имён и дополнения хранятся в SQLite. Для резервной копии остановите локальный сервер и скопируйте папки `data` и `.family` в закрытое хранилище.

Для масштаба и перемещения используется локальная копия D3. Исходная геометрия Coggle сохранена в `data/layout.json`. Ингушская терминология сверена со словарём [PaydaDosh](https://paydadosh.ru/).

## Размещение для родственников

### GitHub → ONREZA

Первый релиз включает 748 записей из PDF и двух подтверждённых родственников из `data/published-additions.json`. У обоих сохранены исходные идентификаторы и ссылки на отцов. Репозиторий содержит имена и родственные связи. Для семейного проекта подойдёт приватный репозиторий.

1. Под аккаунтом `aliskhannn` создайте пустой репозиторий `khutiev-tree`. Оставьте автоматическое создание README, лицензии и .gitignore выключенным. В этой локальной копии уже настроен `origin`. [Создать репозиторий на GitHub](https://github.com/new)

   ```bash
   cd ~/Projects/khutiev-tree
   git push -u origin main
   ```

2. В ONREZA выберите план **Hobby**. В **Workspace → Settings → Git → GitHub** установите GitHub App и дайте ей доступ к `aliskhannn/khutiev-tree`. Если панель просит привязать профиль GitHub, это делается в **Account → Settings → Authentication**. Затем создайте проект из подключённого репозитория, выберите ветку `main`. [Подключение Git-провайдера](https://docs.onreza.ru/git-integration/)

3. Выберите **Other**, **Node.js 24**, корневую папку `.`. Значения для сборки перечислены ниже и записаны в `onreza.toml`. Для следующих публикаций включите **Auto Deploy** на ветке `main`. [Настройки сборки](https://docs.onreza.ru/projects/build-settings.html)

   | Настройка | Значение |
   | --- | --- |
   | Install Command | `pnpm install --frozen-lockfile` |
   | Build Command | `node scripts/build-onreza.mjs` |
   | Output Directory | `build-onreza` |
   | Runtime | Node.js, Compute (PROCESS) |
   | Точка входа внутри сборки | `server/onreza.mjs` |

4. Откройте раздел **PostgreSQL** в workspace, создайте базу и подключите её к сервису сайта и его окружению **Production**. Выберите основную ветку базы и включите **Auto-inject** для `DATABASE_URL`. Таблицы создаются при первом запуске. Здесь сохраняются новые заявки, решения редактора и исправления имён. [Подключение PostgreSQL](https://docs.onreza.ru/integrations/postgresql.html)

5. В переменных окружения **Production** добавьте два секрета. `EDITOR_CODE` — пароль для входа в редактор. `SESSION_SECRET` — отдельный случайный ключ для сессий редактора. Для каждого можно отдельно выполнить `openssl rand -hex 32` или воспользоваться генератором в менеджере паролей. Порт назначает платформа. При необходимости можно задать `FAMILY_ORIGIN` равным точному публичному HTTPS-адресу сайта. [Переменные окружения](https://docs.onreza.ru/env-vars.html)

6. Нажмите **Deploy**. Если импорт уже запустил первую сборку до подключения базы и секретов, выберите **Redeploy**. Откройте выданный HTTPS-адрес. При первом запуске счётчик показывает 750 человек. Для проверки входа откройте `/#editor` на этом адресе и введите `EDITOR_CODE`.

Подписка Hobby стоит 0 ₽ и даёт общий кредит 250 ₽ в месяц на ресурсы, включая Compute и PostgreSQL. При исчерпании кредита платные ресурсы приостанавливаются до следующего периода. ### Публикация семейного дерева

Для этой версии с открытым просмотром и формой «Добавить сына» выбирайте хостинг, у которого рабочая база физически размещена в России. Архив содержит исходные имена и связи в `data/people.json` и дополнения в `.family/tree.sqlite`. alwaysdata указывает, что его серверы находятся во Франции. При сборе персональных данных граждан РФ действует общее правило локализации. [Расположение серверов alwaysdata](https://help.alwaysdata.com/en/docs/technical-specifications/architecture/) · [Часть 5 статьи 18 закона № 152-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_61801/cbf4e15b7c330f9372e876cdf2bc928bad7950ef/)

Имя вместе с отцовской линией и названием тейпа может позволить узнать конкретного человека. До открытия дерева для всех установите основание для публикации таких записей. Если основанием служит согласие человека, разрешение на распространение оформляется отдельно. Это касается и имён из уже опубликованной семейной схемы. [Статья 3](https://www.consultant.ru/document/cons_doc_LAW_61801/4f41fe599ce341751e4e34dc50a4b676674c1416/) · [Статья 10.1](https://www.consultant.ru/document/cons_doc_LAW_61801/591acc70f577873c1ee54765eda110b7a0271eaf/)

### Запуск на выбранном хостинге

Сайт можно запустить на хостинге с Node.js и постоянным диском. Направьте HTTPS-домен через обратный прокси на сервер и задайте `FAMILY_ORIGIN` равным внешнему адресу, например `https://example.org`. Порт задаётся через `PORT`, адрес прослушивания через `FAMILY_HOST`, каталог постоянных данных через `FAMILY_STATE_DIR`.

Для Sites сборка `node scripts/build.mjs` создаёт серверный модуль в `dist/server`. Привязка базы D1 называется `DB`, миграции базы хранятся в `drizzle/`. Пароль `EDITOR_CODE` и ключ подписи `SESSION_SECRET` задаются как секреты среды перед развёртыванием. Локальная база и файлы с кодами исключены из репозитория и сборки.
